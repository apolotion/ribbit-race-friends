RIBBIT RACE — FRIENDS EDITION
Complete GitHub + Cloudflare setup
Build 2026.09.25-friends-1

IMPORTANT: THIS IS A NEW PERSONAL INSTALLATION.
Do not paste these files into your school Google Sheet updater, Code.gs, or OnlineVersus.gs. Leave the school game and student database unchanged. Friends start with new accounts; no school records are copied. The package is prepared, not already deployed.

WHAT YOU ARE DEPLOYING
One Cloudflare Worker serves the complete game, account API and WebSocket server on the same public origin. Two SQLite-backed Durable Object classes are configured automatically. GitHub stores source code; it is not the running multiplayer server. A GitHub Pages/static-only upload cannot provide this backend.

You do not need a Google account for players, a school email, a purchased domain, a Google Sheet, a D1 database ID, an API key in the HTML, a TURN service, or router port forwarding. You, as owner, need your own GitHub and Cloudflare accounts.

A. RECOMMENDED: GITHUB + CLOUDFLARE BUILDS

1. Extract the complete ZIP.
   Open the Ribbit_Race_Friends_Cloudflare folder. At its root you should see:

   package.json
   wrangler.jsonc
   README.md
   INSTALL.txt
   public/
   src/
   scripts/
   tests/

   Upload this folder's CONTENTS, not the ZIP and not an extra nesting layer.

2. Create a NEW GitHub repository in your personal account.
   Suggested name: ribbit-race-friends
   Choose Private to keep the source repository private.
   Use GitHub's New repository flow, then upload files (or Add file → Upload files).
   Drag in the extracted contents, preserving the subfolders, and commit to main.

   Confirm GitHub displays package.json and wrangler.jsonc at the repository root,
   and public/index.html contains the complete game. Do not upload old school
   files, student spreadsheets, private save-key files, cookies, .env files or tokens.
   Private source does not mean the deployed game link is private.

3. Create a NEW Cloudflare Worker from this repository.
   Sign in to your personal Cloudflare account.
   Open Workers & Pages → Create application.
   Choose the GitHub/import-repository path for a WORKER.
   Connect GitHub and authorize only the new friends repository when offered.
   Select ribbit-race-friends and the main branch.

   Do not choose a static-only Pages or GitHub Pages deployment. The backend is
   part of this package. A screen asking only for a static build-output directory
   is not enough to deploy these Durable Object classes.

4. Use these settings.

   Worker name:       ribbit-race-friends
   Production branch: main
   Root directory:    repository root (leave blank, or / when required)
   Build command:     npm run check && npm test
   Deploy command:    npx wrangler deploy
   Node version:      22 or newer supported release

   Cloudflare installs the project's npm dependency as part of its build flow.
   If you need to override the build image, set its build variable NODE_VERSION
   to 22.16.0 or a newer supported Node 22/24 release. The game itself needs no
   JavaScript framework compilation: the build command runs checks.

   Keep the Worker name identical to the "name" in wrangler.jsonc. If that name
   is already used by an older incompatible Worker, choose a NEW name in both
   places before the first deployment. Do not silently replace an old school
   or personal server that another game still uses.

   Cloudflare Builds can generate its deployment credential within Cloudflare.
   Do not put a Cloudflare API token in game HTML or in the GitHub source.
   The package has no player-provider secret to paste into either place.

5. Deploy and wait for success.
   Wrangler reads wrangler.jsonc and provisions the FriendsHub and FriendsRoom
   SQLite namespaces/migrations along with the public/ assets. It does not ask
   you to create a separate D1 or KV database.

   In Worker settings, verify the bindings:
      HUB    → FriendsHub
      ROOMS  → FriendsRoom
      ASSETS → public static assets

   Follow the deployment log if the build fails. Do not remove the SQLite
   migration or change the classes just to dismiss an error.

6. Open the public workers.dev URL Cloudflare gives you.
   It will resemble:
      https://ribbit-race-friends.YOUR-SUBDOMAIN.workers.dev

   That is an EXAMPLE, not an already created link. Copy the actual deployment
   URL from your dashboard. Friends share that URL, not a GitHub file URL,
   a school /exec address, or the source copier.

   Do not enable a Cloudflare Access email restriction for this public game.
   The application's own optional cloud account is all a friend needs.

   Open the URL in a private/incognito browser window while signed out of Google.
   You should see FRIENDS EDITION · CLOUD SAVE with a username and private-key
   login, Create Account, and Play Without Saving.

   Append /api/health to the actual game URL. Expected JSON includes:
      "ok": true
      "friendsVersion": 1
      "build": "2026.09.25-friends-1"
      "transport": "cloudflare-websocket"

7. Test before wider sharing.
   Use TWO different browser profiles/devices and two different accounts or guests.
   Prefer a test across two real networks, such as home Wi-Fi and a friend's home.

   Create Account → choose an alias → copy/download the private key → acknowledge
   that the key is saved → Play. Never send the private key to another player.
   To load the same save elsewhere, sign in using that username and private key.

   Test private online play:
      Both: Versus → Wi-Fi
      Player A: Host
      Player B: Join → enter A's five-character room code
      Pick different frogs in a private room.
      Both: Ready

   Confirm SERVER ... MS, matching prompts/scores, responsive controls, full jumps,
   and a shared match result. Then test Quickplay with both players in its queue.
   Quickplay cannot find an opponent when nobody else is waiting.

   Test a saved achievement/record: use Save Now, reload, then sign in from the
   second browser profile and verify that progress returns. Test an opponent's
   deliberate departure and the level-five CPU replacement.

   Online Escape is an exit menu, not a pause button. Keep the host computer awake
   and the game tab active for the lowest risk of browser scheduling interruption.

B. ALTERNATIVE: FIRST DEPLOY FROM YOUR COMPUTER

Use this path when the dashboard import flow is confusing. Run commands from the
extracted folder that contains package.json and wrangler.jsonc.

1. Install a supported Node.js release (22 or newer). Then open Terminal on macOS
   or PowerShell on Windows. Change directory into the extracted project folder.
   Example only:
      cd path/to/Ribbit_Race_Friends_Cloudflare

2. Run these commands in order:

   npm install
   npm run check
   npm test
   npx wrangler login
   npm run deploy

   Log in to your PERSONAL Cloudflare account in the browser window opened by
   Wrangler. Select the intended account when you own more than one.
   npm install downloads the pinned Wrangler version and creates package-lock.json.
   Keep the lockfile in GitHub, but do not commit node_modules or .wrangler.

3. Copy the workers.dev link printed after deployment and perform section A.6–7.
   Only the owner needs these tools; friends play in their browser.

   Optional local preview (a separate local database, not production):
      npm run dev

   Optional explicit HTTP smoke test after deploying:
      npm run smoke -- https://YOUR-ACTUAL-GAME-URL.workers.dev

   The smoke test creates and then deletes ONE temporary account. It verifies
   accounts/saves/API checks, not real two-player latency. Do not run it repeatedly
   against someone else's server or real friend's account. It counts against
   this package's signup/rate limits.

4. To connect future updates from GitHub after a CLI-first deployment:
   Put the same project contents in the new personal GitHub repository.
   In Cloudflare, select this Worker → Settings → Builds → Git repository.
   Connect the repository and set the same commands from A.4.
   Future main-branch commits can then build/deploy automatically.

C. UPDATING WORDS, GAME CODE AND SETTINGS

Words:
Edit src/vocabulary.json in GitHub, retain the english/spanish object format,
commit to main, wait for Cloudflare deployment, and use Refresh Words or reopen.
The current package starts with the approved 20 entries without articles.
This does not update the school Vocabulary sheet. The offline HTML fallback is
separate and stays on its embedded release list until that HTML is updated.

Game/server updates:
Change the corresponding files in the Friends repository, preserving directories.
Commit and deploy the complete matching update. Stop live matches first, then
refresh both devices. Do not use the school Sheet's Game Updates menu here.
The companion source copier contains complete files, not patches. The entire ZIP
is simplest for the first upload; copying public/index.html alone is not a server.

Runtime limits:
The wrangler.jsonc defaults are MAX_ACCOUNTS="500" and ALLOW_REGISTRATION="true".
These are ordinary settings, not private credentials. Close new accounts by
changing ALLOW_REGISTRATION to "false" and redeploying. Existing accounts and
public guest access remain. An account cap is not a traffic or spending cap.

Rollback:
Revert the Friends Git commit and redeploy the prior compatible code. Keep the
Worker name, HUB/ROOMS bindings, class names, hub instance name and migrations.
Do not delete the Worker or database namespaces to roll back a UI change.
Cloud save exports are available to each user under Back Up / Manage Save;
automatic JSON import is not part of this release.

D. COST AND RELIABILITY

Cloudflare currently supports SQLite-backed Durable Objects on Workers Free.
Daily free quotas can stop affected operations when exhausted. A small test does
not establish that repeated matches will remain inside those quotas. Active
WebSocket traffic, hub/control calls, replay writes, storage and CPU all matter.
Workers Paid starts with a base charge and can add usage charges. Check the
current official pricing pages and your own account's usage/billing dashboard.
The package uses hibernation-compatible WebSockets; active games still consume
resources. There is no configured hard monetary cap or Turnstile deployment.

Cloudflare hosts a real low-overhead WebSocket relay, but this is not a promise of
"lagless" internet. The host's browser remains authoritative for game physics.
The game is for casual friends, not tamper-proof competition. Network distance,
packet loss, regional room placement, sleeping computers, tab suspension and
provider limits still affect it. Prefer wired/stable Wi-Fi and nearby players.

E. TROUBLESHOOTING

The login still says Student ID or Google:
You opened the school or older link. Use the new Worker URL and check its build.

JSON API errors / 404 / account buttons cannot reach the server:
Deploy the complete Worker project, not public/index.html alone or GitHub Pages.
Verify the public/ assets binding and src/index.js as the Worker entry point.

Missing package.json or configuration:
The uploaded repository has an extra parent folder. Move contents to the root or
set the root directory to that exact folder in Cloudflare build settings.

Missing HUB / ROOMS / SQLite migration error:
Verify both Durable Object exports in src/index.js and the supplied wrangler.jsonc.
Make sure this is a new Worker installation. Do not replace new_sqlite_classes
with an old key-value migration. Share the deployment error with secrets removed.

Username or key not recognized:
Use the Friends username and private key, not the school's ID/PIN. Keep the actual
hostname consistent. A new Worker/database is a different set of accounts.

Account changed in another tab:
Refresh that game tab. Signing in as another account or replacing the key changes
the authenticated session. This guard prevents writing one person's progress into
another person's account.

Quickplay keeps searching:
Have a second player use this SAME Friends deployment and queue at the same time.
School and Friends queues do not mix.

Room expired / cannot reconnect after refresh:
Create a new room. Active in-memory match recovery is not a cross-refresh game save.

WebSocket cannot connect:
Use the direct HTTPS game origin, not an iframe or local file. Check browser console,
network policy and the Worker's API availability. Friends WebSockets do not require
WebRTC, TURN or router port forwarding. A network can still block the service.

Too many requests / new accounts temporarily unavailable:
Respect rate limits or wait for their window. Check the configured account cap and
Cloudflare quotas. Do not remove all rate limits from a public deployment.

F. TESTING LIMITS OF THIS PACKAGE

Syntax, room/save unit tests, HTTP integration checks, and browser flows were run.
Successful browser multiplayer tests used a test-only network bridge and a local
Node SQLite/Durable Object adapter. The actual game and backend logic executed,
but not in Cloudflare workerd or a deployed account. Native Chromium networking
was managed-policy blocked in the build environment. Wrangler could not be
installed here, and this exact package was not deployed. See TEST_REPORT.txt.
